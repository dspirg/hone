## Design System

| Property | Value |
|----------|-------|
| Tool | none (SwiftUI asset catalog + Theme.swift) |
| Preset | not applicable |
| Component library | SwiftUI native |
| Icon library | SF Symbols |
| Font | SF Pro (system default via `.font()` — no custom typeface) |

Source: CONTEXT.md D-01 (discretion on Theme.swift vs asset-catalog-only), CLAUDE.md technology stack.

**Architecture decision (D-01):** Use a centralized `Theme.swift` that exposes static `Color` constants drawn from the asset catalog. This gives a single call site to update later while letting dark-variant activation stay in xcassets. Views reference `Theme.accent`, `Theme.background`, `Theme.surface`, etc. — never raw hex strings or `Color("AccentColor")` directly.

## Spacing Scale

All spacing values are multiples of 4, matching the sketch theme and existing codebase patterns (`.planning/sketches/themes/default.css`, sampled view padding across 41 Swift files).

| Token | Value | SwiftUI Constant | Usage |
|-------|-------|-----------------|-------|
| xs | 4pt | `Theme.Spacing.xs` | Icon gaps, inline label padding, caption offset |
| sm | 8pt | `Theme.Spacing.sm` | Compact element spacing, chip internal padding, timestamp offset |
| md | 16pt | `Theme.Spacing.md` | Default horizontal screen padding, section insets |
| lg | 24pt | `Theme.Spacing.lg` | Between major UI sections, card internal padding |
| xl | 32pt | `Theme.Spacing.xl` | Page-level vertical breathing room |
| 2xl | 48pt | `Theme.Spacing.xxl` | Major section breaks, loading animation spacers |
| 3xl | 64pt | `Theme.Spacing.xxxl` | Rarely used — full-bleed hero spacing only |

Exceptions:
- Touch targets (buttons, tab items): minimum 44pt height — iOS HIG minimum (not a spacing token, enforced with `.frame(minHeight: 44)`).
- Thumbnail size: 52x52pt — existing codebase standard from `ExerciseLibraryRowView`. Not a spacing token.
- Chat bubble internal padding: 12pt — existing implementation, kept as-is.

## Typography

SwiftUI Dynamic Type text styles are used throughout. No custom type sizes are introduced — Phase 10 is a color and identity migration, not a typography overhaul (CONTEXT.md D-04: "Colors only for this phase — no typography standards").

The table below documents the existing type roles as observed in the codebase, to provide a stable reference for Phase 10 changes that touch text color.

| Role | SwiftUI Style | Approx Size | Weight | Line Height |
|------|--------------|-------------|--------|-------------|
| Caption | `.caption` / `.caption2` | 11–12pt | Regular (400) | 1.3 |
| Body / Label | `.body` / `.subheadline` | 15–17pt | Regular (400) or Semibold (600) | 1.5 |
| Heading | `.headline` / `.title2` | 20–22pt | Semibold (600) | 1.3 |
| Display | `.title` / `.largeTitle` | 28–34pt | Semibold (600) | 1.2 |

Rules for Phase 10:
- All text color changes must use semantic roles only: `.primary`, `.secondary`, `.tertiary` — these activate automatically in forced dark mode.
- Do NOT hardcode `.white` or `.black` for text. Exception: text on top of accent-color fills (e.g. primary CTA button label), which must use `.white` explicitly.
- `Theme.accent` (`#f59e0b`) is used for tinted icon foreground, not for body text.

### Asset Catalog Updates

Three existing color sets must be updated; dark variants are authoritative (D-14 forces `.preferredColorScheme(.dark)` at root). Light variants are kept to preserve infrastructure (D-15).

| `CardBackground` | `#1C1C1E` (≈28, 28, 30) | `#161616` | `#ffffff` |

### New Color Sets to Add

| Color Set Name | Dark Value | Light Value | Semantic Purpose |
|---------------|------------|-------------|-----------------|
| `SurfaceElevated` | `#1e1e1e` | `#f0f0f0` | Cards above CardBackground; modal sheets |

| `SuccessGreen` | `#34d399` | `#059669` | Personal records, completed states |
| `DestructiveRed` | `#f87171` | `#dc2626` | Delete actions, error states only |

### 60 / 30 / 10 Distribution

| Role | Value | Asset Catalog Set | Usage |
|------|-------|------------------|-------|
| Dominant (60%) | `#0a0a0a` | `AppBackground` | Screen background, navigation background |
| Secondary (30%) | `#161616` | `CardBackground` | Cards, list rows, sheet surfaces, tab bar background |
| Accent (10%) | `#f59e0b` | `AccentColor` | See reserved-for list below |
| Destructive | `#f87171` | `DestructiveRed` | Delete and irreversible action labels only |

**Accent (`#f59e0b`) is reserved exclusively for:**
1. Primary CTA button fill (full-width action buttons)
2. Active tab bar icon
3. Progress ring stroke (weekly ring)
4. Loading animation ring strokes (pulsing rings in plan generation)
5. Hone avatar gradient start color (amber-to-orange)
6. Chat bubble background for user messages (replaces current AccentColor reference in `ChatBubbleView`)
7. `.tint()` modifier on interactive controls (toggles, sliders)
8. Thumbnail tap affordance overlay (brief amber flash on tap)

Accent must NOT be used for: body text, section headings, background fills, decorative borders, or secondary information labels.

### Hone Avatar Gradient

Source: CONTEXT.md D-05.

The Hone coach avatar is a warm gradient circle — no face or character.

```
Linear gradient, 135 degrees
Start: #f59e0b (amber)
End:   #f97316 (orange-500)
```

Applied as: `LinearGradient(colors: [Theme.accent, Color(hex: "#f97316")], startPoint: .topLeading, endPoint: .bottomTrailing)` clipped to a circle.

Diameter in chat header: 36pt. Diameter in home screen coach card: 48pt.

### Chat Bubble Styling

## Hone Identity Contract

Source: CONTEXT.md D-05 through D-09, REQUIREMENTS.md UI-06, MANIFEST.md.

### Name

Everywhere the app previously displayed "Coach" or a generic label, it now displays "Hone".

| Location | Old text | New text |
|----------|----------|----------|
| `CoachHeaderView` | "Coach" | "Hone" |
| `ChatBubbleView` coach label | "Coach" | "Hone" |
| Plan generation loading | "Analyzing your goals..." (unchanged) | Add byline: "Hone is on it." |
| Adaptation summary | Generic system text | "Hone adjusted your plan — [reason]." |
| Re-engagement notification title | "Your plan is ready" | "Hone updated your plan" |
| Workout reminder title | "Ready for your [type] day?" | "Hone: your [type] session is ready" |

### Personality Tone (D-07)

Warm, direct, and confident — premium gym trainer who knows you personally. Not clinical or corporate.

- Use active voice: "Hone adjusted..." not "Your plan was adjusted..."
- Lead with the outcome: "Stronger push muscles — here's your updated session."
- Motivational nudge is brief (1 sentence max) — never preachy.
- No exclamation points in system messages. One allowed per notification copy.

### System Messages (D-09)

Format: `"Hone [verb]... — [outcome/reason]."`

Examples:
- "Hone lightened Wednesday's load — you had a tough week."
- "Hone added a rest day — your body earns recovery."
- "Hone refreshed your plan — you're ready for the next level."

## Video Thumbnail Contract

Source: CONTEXT.md D-10 through D-13, REQUIREMENTS.md UI-02, UI-03.

### Thumbnail Source

URL pattern: `https://image.mux.com/{muxPlaybackId}/thumbnail.jpg?time=0&width=200`

Computed in `ExerciseModel.thumbnailURL` (already exists). No change needed to model.

### Thumbnail Dimensions by Context

| Context | Size | Corner Radius | Tap Action |
|---------|------|--------------|------------|
| Exercise library row | 52x52pt | 8pt | Opens fullscreen video overlay |
| Session exercise card | 80x80pt | 10pt | Opens fullscreen video overlay |
| Plan preview exercise row | 52x52pt | 8pt | Opens fullscreen video overlay |
| Coach chat exercise mention | 44x44pt | 6pt | Opens fullscreen video overlay |

### Placeholder (Missing Thumbnail)

When `muxPlaybackId` is nil or image load fails:

- Background: `CardBackground` fill
- Icon: `Image(systemName: "dumbbell")` at `.body` font size
- Foreground: `Color(UIColor.tertiaryLabel)` — matches existing `ExerciseLibraryRowView` pattern

### Fullscreen Video Overlay (D-11)

Implementation: `.fullScreenCover` with `AVPlayerViewController` wrapped in `UIViewControllerRepresentable`.

- Presentation: `.fullScreenCover` from any view that holds a thumbnail (not `.sheet` — sheet shows partial cover on iPad)
- Dismiss: native `AVPlayerViewController` close button (top-left X) + swipe-down gesture
- Background: black (`Color.black.ignoresSafeArea()`)
- Autoplay: yes — video starts on overlay appear
- Loop: yes — `AVPlayerLooper` for continuous playback
- Controls: standard `AVPlayerViewController` transport controls
- Accessibility label on thumbnail: "[exercise name] — tap to play video"

## Dark Mode Migration Contract

Source: CONTEXT.md D-14 through D-16, REQUIREMENTS.md UI-01.

| Rule | Detail |
