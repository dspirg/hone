# Phase 1 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — iOS native (SwiftUI HIG) |
| Preset | not applicable |
| Component library | SwiftUI native views (no third-party component library) |
| Icon library | SF Symbols 5 (system icons bundled with iOS 17+) |
| Font | SF Pro (system default; no custom font in Phase 1) |

**Note:** This is an iOS-only SwiftUI project. shadcn, Tailwind, and web component libraries are not applicable. Design tokens map to SwiftUI spacing/font constants, not CSS variables.

---

## Spacing Scale

iOS HIG minimum touch target: 44pt. All values in SwiftUI points (1pt = 1px on non-Retina; scales with display density automatically).

Declared values (multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-label gaps, inline divider insets |
| sm | 8pt | Compact element spacing (e.g., field label above text field) |
| md | 16pt | Default horizontal content margin, form field internal padding |
| lg | 24pt | Section padding, button vertical padding |
| xl | 32pt | Between major form sections |
| 2xl | 48pt | Vertical breathing room above/below primary CTA |
| 3xl | 64pt | Top safe area clearance for full-screen modal content |

Exceptions:
- Touch targets: minimum 44pt height for all tappable elements (iOS HIG requirement). Applies to "Forgot password?" link, tab bar items, and "I Understand" button.
- Tab bar: height is system-managed by SwiftUI `TabView`; do not override.
- "Sign in with Apple" button: minimum 44pt height enforced by `ASAuthorizationAppleIDButton` (Apple requirement).

## Typography

All sizes in SwiftUI points. Font is SF Pro (system default via `.font()` modifier). No custom typeface in Phase 1.

| Role | Size | Weight | Line Height | SwiftUI Token |
|------|------|--------|-------------|---------------|
| Body | 17pt | Regular (400) | 1.5 | `.body` |
| Label | 15pt | Regular (400) | 1.4 | `.subheadline` |
| Heading | 22pt | Semibold (600) | 1.2 | `.title2` |
| Display | 28pt | Semibold (600) | 1.1 | `.title` |

**Constraints:**
- Maximum 2 weights in Phase 1: Regular (400) for body/label, Semibold (600) for headings and display.
- No italic usage in Phase 1.
- Dynamic Type: all text must use SwiftUI semantic font tokens (`.body`, `.title2`, etc.) — never fixed pixel values — so iOS accessibility scaling works automatically.

## Color

Phase 1 targets a dark-mode-first fitness aesthetic. Colors are defined as semantic roles; light mode variants are mapped for system respect.

| Role | Dark Mode | Light Mode | Usage |
|------|-----------|------------|-------|
| Dominant (60%) | `#0F0F0F` (near-black) | `#F5F5F5` (near-white) | App background, full-screen surface |
| Secondary (30%) | `#1C1C1E` (system grouped bg) | `#FFFFFF` (white) | Cards, form fields, tab bar background, modal sheet surface |
| Accent (10%) | `#FF6B35` (energetic orange) | `#FF6B35` (same) | Primary CTA button fill, active tab indicator, "I Understand" button |
| Destructive | `#FF3B30` (iOS system red) | `#FF3B30` (same) | Sign out confirmation (Phase 1), future delete actions |

**SwiftUI semantic mappings:**
- Dominant: `.systemBackground` / `Color("AppBackground")`
- Secondary: `.secondarySystemBackground` / `Color("CardBackground")`
- Accent: `Color("AccentColor")` — set as the app accent color in Assets.xcassets
- Destructive: `Color.red` (SwiftUI system) / `.systemRed`

Accent reserved for:
1. "Sign in with Apple" button — styled per Apple requirements (black/white, not accent — system-enforced)
2. "Sign In" / "Create Account" primary CTA button fill
3. "I Understand" disclaimer button fill
4. Active tab bar item icon + label tint
5. Focused text field border highlight

Accent is NOT used for: body text, headings, labels, secondary buttons, dividers, background surfaces, or placeholder text.

**Source:** Dominant/secondary from iOS system semantic colors (auto dark/light). Accent `#FF6B35` chosen as discretion — energetic orange reads as active/fitness-forward on dark surfaces without being aggressive. (Source: Claude's Discretion — color not specified in CONTEXT.md.)

## Interaction Contracts

### Disclaimer Modal (D-06, D-07)

- Presentation: `.fullScreenCover` on first launch, before auth, before any content
- Dismissal: single "I Understand" button (accent fill) — no swipe-to-dismiss, no X button
- Persistence: `UserDefaults` key `disclaimerAcknowledged` — shown once only
- Button state: always enabled (no checkbox required — single-tap acknowledgment)

### Auth Screen (D-01, D-02, D-03)

- Layout: Segmented control or custom tab toggle at top — "Log In" / "Sign Up" (equal width)
- Apple Sign-In: `ASAuthorizationAppleIDButton` (`.signIn` style for login state, `.signUp` for sign-up state) — rendered above divider
- Divider: centered "— or —" in Label style, color `.tertiaryLabel`
- Email/Password fields: standard SwiftUI `TextField` (email) + `SecureField` (password), labeled above each field in Label style
- Primary CTA: "Sign In" (login state) / "Create Account" (sign-up state) — full-width, accent fill, 52pt height, 12pt corner radius
- "Forgot password?": right-aligned below password field, Label size, accent color, login state only
- Error display: inline below the relevant field in Label size, destructive color — no alert dialogs for field validation
- Loading state: primary CTA shows `ProgressView` replacing button label; button disabled; Apple button disabled

### Password Reset Screen

- Navigation: `.navigationDestination` push (not modal)
- Single email field with "Send Reset Link" primary CTA
- Success state: replace form with confirmation message (heading + body), no CTA — user exits via back button
- Back button: system "Back" label, standard SwiftUI navigation

### Tab Bar Shell (D-04, D-05)

- SwiftUI `TabView` with 4 items
- Tab items (in order): Home, Train, Coach, Profile
- Icons: SF Symbols — `house.fill` / `figure.strengthtraining.traditional` / `message.fill` / `person.fill` (filled variant for selected state; outlined for unselected)
- Tab labels: "Home", "Train", "Coach", "Profile" — Label size
- Active tab: accent tint on icon + label
- Transitions between tabs: default SwiftUI tab switch (no custom animation)

### Empty State Views (all 4 tabs)

- Each tab shows a centered vertical stack: SF Symbol illustration (large, secondary color) + Heading + Body text
- No CTAs on empty states in Phase 1 (future phases add actions)

## Accessibility Contract

- All interactive elements have `.accessibilityLabel` set (custom labels where SF Symbol alone is ambiguous)
- Minimum touch target: 44pt x 44pt (enforced via `.frame(minWidth: 44, minHeight: 44)` where needed)
- Dynamic Type: all text uses semantic SwiftUI font tokens — never `.system(size: N)`
- Color contrast: accent `#FF6B35` on `#0F0F0F` background = 4.6:1 (meets WCAG AA for large text; acceptable for UI components per WCAG 2.1 §1.4.11)
- VoiceOver: `TabView` items labeled with full names; disclaimer modal announces itself as a required acknowledgment screen
- "Sign in with Apple" button: Apple's `ASAuthorizationAppleIDButton` is inherently accessible
