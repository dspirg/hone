<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| User input -> AuthViewModel | Email, password, display name from untrusted text fields |
| Apple identity token -> Supabase Auth | Token crosses from Apple framework to Supabase backend |
| Nonce generation -> Apple request | Cryptographic nonce must use secure randomness |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 | Spoofing | SignInWithAppleButton.swift | mitigate | SHA-256 nonce via CryptoKit with SecRandomCopyBytes (not arc4random); raw nonce sent to Supabase, hash sent to Apple; prevents replay attacks |
| T-03-02 | Information Disclosure | AuthViewModel.swift | mitigate | Error messages use generic user-facing copy (mapAuthError); never expose raw Supabase/GoTrue error internals to UI |
| T-03-03 | Tampering | Password field | mitigate | SecureField masks password input; password transmitted over HTTPS to Supabase Auth; never logged or stored locally |
| T-03-04 | Denial of Service | Auth CTA button | mitigate | Button disabled during isLoading state; prevents double-submission of auth requests |
| T-03-05 | Information Disclosure | DisclaimerView.swift | accept | Disclaimer acknowledged flag in UserDefaults (not Keychain); this is a non-sensitive boolean (not a token or credential); acceptable per CONTEXT.md D-07 |
| T-03-06 | Spoofing | Apple Sign-In fullName | mitigate | fullName captured and written to profiles table immediately on first sign-in (Pitfall 1); prevents permanent blank display name |
</threat_model>
