Step 2: Only if all tests pass — push the Supabase migration.

The push command requires the Supabase access token. Set it via the environment variable to avoid interactive prompts:

```bash
cd /Users/Fish/Desktop/workout
export SUPABASE_ACCESS_TOKEN=$(cat ~/.supabase/access-token 2>/dev/null || echo "")
supabase db push
```

If `SUPABASE_ACCESS_TOKEN` is empty (token file not found), the command will prompt for login. In that case:
1. Run `supabase login` to authenticate
2. Then re-run `supabase db push`

Expected output on success:
```
Applying migration 20260422000000_create_session_logs.sql...
Finished supabase db push.
```

Step 3: Verify the tables were created by checking the migration status:

```bash
supabase migration list
```

```bash
supabase db execute "SELECT tablename, rowsecurity FROM pg_tables WHERE schemaname = 'public' AND tablename IN ('session_logs', 'set_logs');"
```

Expected output: `rowsecurity = t` for both tables.
