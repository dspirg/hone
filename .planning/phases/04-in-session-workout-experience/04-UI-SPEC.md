# Phase 4 — UI Design Contract

> Visual and interaction contract for Phase 4: In-Session Workout Experience. Generated by gsd-ui-researcher.
> This phase inherits all Phase 1 and Phase 2 tokens and extends them for the session execution screens.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — iOS native (SwiftUI HIG) |
| Preset | not applicable |
| Component library | SwiftUI native views (no third-party component library) |

| Font | SF Pro (system default; no custom font) |

**Note:** iOS-only SwiftUI project. shadcn, Tailwind, and web component libraries are not applicable. All design tokens map to SwiftUI spacing/font constants. This phase inherits all Phase 1 and Phase 2 tokens. (Source: Phase 2 UI-SPEC; CONTEXT.md established patterns.)

## Spacing Scale

Inherits Phase 2 scale unchanged. All values in SwiftUI points.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-label gaps; set row internal leading/trailing padding; progress bar segment gap |
| sm | 8pt | Between set rows; between stepper controls and rep count; progress label below bar |
| md | 16pt | Default horizontal content margin; card internal padding; set row vertical padding |
| lg | 24pt | Section divider spacing; vertical gap between video and set log area |
| xl | 32pt | Horizontal edge padding on session summary body content (matches detail view) |
| 2xl | 48pt | Vertical breathing room on summary completion screen above icon |
| 3xl | 64pt | Rest timer overlay: vertical margin above circular ring from screen top |

Exceptions:
- Touch targets: minimum 44pt on all tappable elements (stepper +/− buttons, checkmark tap, Skip Rest, +30s, Done). Steppers use `.contentShape(Rectangle())` to extend hit area.
- Stepper button size: 36pt visual, 44pt touch target.
- Checkmark button: 44pt × 44pt minimum touch target.
- Rest timer circular ring: 200pt × 200pt frame (consistent with code examples in RESEARCH.md Pattern 1).
- Tab bar: height system-managed by SwiftUI `TabView`; do not override.

## Typography

Inherits Phase 2 scale — maximum 4 sizes, maximum 2 weights. All in SwiftUI points. Dynamic Type required.

| Role | Size | Weight | Line Height | SwiftUI Token |
|------|------|--------|-------------|---------------|
| Body | 17pt | Regular (400) | 1.5 | `.body` |
| Label | 15pt | Regular (400) | 1.4 | `.subheadline` |
| Heading | 22pt | Semibold (600) | 1.2 | `.title2` |
| Display | 28pt | Semibold (600) | 1.1 | `.title` |

Phase 4 role assignments (no new sizes or weights introduced):

| UI Element | Role | Notes |
|------------|------|-------|
| Exercise name on card | Heading — `.title2` semibold | Consistent with exercise detail view |
| "Exercise N of M" progress label | Label — `.subheadline` regular | Secondary color |
| Set row label ("Set 1", "Set 2") | Label — `.subheadline` regular | Primary color |
| Rep count displayed in stepper | Heading — `.title2` semibold | Large enough to tap accurately; monospacedDigit |
| Target reps placeholder ("Target: 8–12") | Label — `.subheadline` regular | `.secondary` color |
| Rest timer countdown number | Display — `.system(size: 64, weight: .semibold, design: .rounded)` | Exception: fixed size for impact in overlay — see note |
| Rest timer "Next up" context label | Label — `.subheadline` regular | `.secondary` color |
| Session summary stat values | Heading — `.title2` semibold | Exercises, sets, reps, duration values |
| Session summary stat labels | Label — `.subheadline` regular | `.secondary` color |
| Session summary duration | Heading — `.title2` semibold | — |
| Sync failure banner message | Label — `.subheadline` regular | Inline banner, `.secondary` |

**Rest timer countdown exception:** `.system(size: 64, weight: .semibold, design: .rounded)` with `.monospacedDigit()` is approved for the rest timer overlay only. The large fixed size is intentional — it must be legible at arm's length under exertion. This is the only place in Phase 4 where a fixed system size is used. All other text uses semantic SwiftUI tokens. (Source: RESEARCH.md Pattern 1 code example; CONTEXT.md "large countdown number, minimal chrome".)

## Color

Inherits Phase 2 color contract. No new semantic colors introduced.

| Role | Dark Mode | Light Mode | Usage |
|------|-----------|------------|-------|
| Dominant (60%) | `#0F0F0F` (near-black) | `#F5F5F5` (near-white) | App background; session card background; rest timer overlay backdrop |
| Secondary (30%) | `#1C1C1E` | `#FFFFFF` | Exercise card surface; set row backgrounds; summary card |
| Accent (10%) | `#FF6B35` (energetic orange) | `#FF6B35` (same) | Circular progress ring tint; checkmark confirmation; completed set indicator |
| Destructive | `#FF3B30` (iOS system red) | `#FF3B30` (same) | "End Session" destructive action only |

**SwiftUI semantic mappings (inherited):**
- Dominant: `Color("AppBackground")`
- Secondary: `Color("CardBackground")`
- Accent: `Color("AccentColor")` via `.tint(Color("AccentColor"))`
- Destructive: `Color.red` — used for "End Session" only

**Accent reserved for (Phase 4):**
1. Circular rest timer progress ring — `.tint(Color("AccentColor"))` on `ProgressView`
2. Checkmark button when tapped to confirm a set complete — fill `Color("AccentColor")`, icon `.white`
3. Completed set row left indicator bar — 3pt vertical bar in `Color("AccentColor")` at full opacity
4. Active tab bar item tint (inherited, Tab 2 Train tab while session is active)

Accent is NOT used for: stepper +/− button fills, set row backgrounds, progress bar fill (use `.secondary` system fill), video player controls, the rest timer backdrop, summary stats, or navigation bar elements.

**Rest timer overlay backdrop:** `Color.black.opacity(0.85)` applied as a ZStack layer above `ExerciseCardView` — not a full `.fullScreenCover`. This preserves `AVPlayer` state in the card beneath. (Source: RESEARCH.md Pitfall 2 and Pattern 1.)

**Progress bar fill (segmented):** System `.tint` on the segmented progress indicator — each completed segment fills with `Color("AccentColor")`. Incomplete segments render in `Color("CardBackground")` with a 1pt border in `.tertiaryLabel`.

**Completed set row state:** background remains `Color("CardBackground")`; leading 3pt accent bar is added; rep count changes from `.primary` to `.secondary`; checkmark icon fills `Color("AccentColor")`.

## Screen Inventory

Phase 4 delivers these screens/views, launched from the Train tab:

| Screen | Type | Trigger |
|--------|------|---------|
| SessionView (root container) | Full-screen NavigationStack push from TrainView | "Start Workout" button on active plan card in TrainView |
| ExerciseCardView (N cards) | Embedded within SessionView ZStack | State-driven by `currentExerciseIndex` |
| RestTimerOverlay | ZStack overlay within SessionView | Automatic on checkmark tap to confirm set |
| SessionSummaryView | ZStack replacement of card area, or NavigationStack push | Last set of last exercise confirmed |
| Sync failure banner | Inline overlay at bottom of SessionView | `syncBannerVisible == true` in SessionSyncService |

No new tabs. No new modal sheets. Session is a full-screen pushed view from TrainView, dismissed back to TrainView via "Done" on the summary.

## Interaction Contracts

### SessionView — Root Session Container

**Entry point:** TrainView shows the active plan summary card with a "Start Workout" button per workout day. Tapping "Start Workout" for a specific `WorkoutDay` NavigationStack-pushes `SessionView`, passing the selected `WorkoutDay`.

**Layout:** Full-screen, no tab bar visible. Navigation bar shows only a back/close button (system "Back" or an "X" close button). No navigation title — the progress bar serves as the session header.

**Progress indicator (top of screen):**
- Text: "Exercise [N] of [M]" — `.subheadline` regular, `.secondary` color, centered.
- Below text: segmented progress bar — `HStack(spacing: 4)` of `M` capsule-shaped segments. Each segment is 4pt tall, equal width (full width minus `md` (16pt) margins and `xs` (4pt) gaps). Completed segments: `Color("AccentColor")`. Current and incomplete segments: `Color("CardBackground")` with `.tertiaryLabel` border.
- Combined height of progress area (text + bar): ~36pt — sits in safe area top padding.

**Card navigation:**
- One `ExerciseCardView` visible at a time.
- Transition: horizontal slide — custom ZStack with `.offset(x: CGFloat(index - currentExerciseIndex) * UIScreen.main.bounds.width)` and `.animation(.spring(response: 0.4, dampingFraction: 0.85), value: currentExerciseIndex)`.
- Advance: "Next Exercise" button at bottom of card (or swipe left gesture) increments `currentExerciseIndex`. On last exercise, "Next Exercise" becomes "Finish Session" which triggers completion flow.
- No backward navigation between exercises during an active session (CONTEXT.md: "No jumping between exercises mid-session").

**Abandonment:** If user taps the system Back button or "X", present a confirmation alert: "End this session?" with "End Session" (destructive) and "Keep Going" (cancel) actions. (Source: CONTEXT.md; destructive action pattern.)

### ExerciseCardView — Full-Screen Exercise Card

**Layout (top to bottom, scrollable):**

1. **Video area (top, full width):** Reuses `VideoPlayerView` from Phase 2. `.aspectRatio(16/9, contentMode: .fit)`. Auto-plays on card appear. Same video states as Phase 2 (buffering spinner, placeholder for missing video, seek-to-zero loop). Video is NOT inside a scroll view — it is a fixed top section.

2. **Exercise metadata (below video, padded `md` 16pt horizontal):**
   - Exercise name: `.title2` semibold, left-aligned.
   - Sets/reps target: `.subheadline` regular, `.secondary` color. Format: "[N] sets × [target reps] reps".

3. **Set log rows (below metadata):** `VStack(spacing: 0)` of `SetLogRow` views, with a `Divider` between each row. No divider after the last row.

4. **"Next Exercise" / "Finish Session" button (bottom, pinned above keyboard):** Full-width `Button` using `.borderedProminent` style, `md` (16pt) horizontal margins, 52pt height. Label: "Next Exercise" or "Finish Session" on last exercise.

**Scroll behavior:** The entire card below the video player (metadata + set rows + button) is a `ScrollView`. Video is outside the scroll view (pinned top). This prevents the video from scrolling out of view on short exercises.

### SetLogRow — Individual Set Row

**Layout (left to right, 52pt minimum height):**
- Leading: Set label — "Set [N]" — `.subheadline` regular, primary color. 48pt wide, left-aligned.
- Center: Stepper control — `HStack(spacing: 12)`: minus button (`minus.circle` SF Symbol, 28pt), rep count (`.title2` semibold, `.monospacedDigit()`, 48pt minimum width, center-aligned), plus button (`plus.circle` SF Symbol, 28pt). The rep count is tappable to open a number pad for direct input.
- Trailing: Checkmark button — `checkmark.circle` SF Symbol when incomplete, `checkmark.circle.fill` with `Color("AccentColor")` tint when completed. 44pt × 44pt touch target.

**Pre-filled state:** Rep count initialized from `PlannedExercise.reps` (target). Displayed as the starting value in the stepper.

**Completed state:** Row leading gets a 3pt vertical accent bar. Checkmark fills accent. Rep count text turns `.secondary`. Row is non-interactive (steppers disabled, checkmark disabled).

**Number pad entry:** Tap on rep count opens a sheet with a numeric `.keypad` keyboard. No decimal. Range: 0–999 (validated before write). "Done" button in the toolbar dismisses and commits. (Source: CONTEXT.md "Tap the rep number to open a number pad for direct input".)

**Set completion action:** Checkmark tap → immediate CoreData write (background context) → rest timer triggers if not the last set of the last exercise. Last set of last exercise → session completion flow (no rest timer).

### RestTimerOverlay — Rest Timer Full-Screen Overlay

**Trigger:** Automatic on `checkmark` tap to confirm a set complete (except last set of last exercise).

**Implementation:** ZStack overlay within `SessionView` (NOT `.fullScreenCover`). Applied above `ExerciseCardView`. `ExerciseCardView` and `VideoPlayerView` remain in the hierarchy beneath.

**Layout (centered vertically on screen):**

```
[backdrop: Color.black.opacity(0.85), ignoresSafeArea]
  VStack(spacing: 32):
    Text("Rest")                    — .subheadline, .secondary, uppercased
    ProgressView(timerInterval: Date()...timerEndDate, countsDown: true)
      .progressViewStyle(.circular)
      .tint(Color("AccentColor"))
      .frame(width: 200, height: 200)
      currentValueLabel: Text(timerEndDate, style: .timer)
                           .font(.system(size: 64, weight: .semibold, design: .rounded))
                           .monospacedDigit()
    Text("Up next: [next set label or exercise name]")
                                    — .subheadline, .secondary
    HStack(spacing: 24):
      Button("+30s")  — .bordered style
      Button("Skip Rest")  — .borderedProminent style
```

**"Next up" context text:**
- If another set remains on the current exercise: "Up next: Set [N+1] — [exercise name]"
- If this was the last set of the current exercise: "Up next: [next exercise name]"

**Timer completion:** Timer expires → haptic feedback (`.sensoryFeedback(.success, trigger: timerJustExpired)`) → soft system sound → overlay auto-dismisses. Background notification cancelled on dismiss or skip.

**Extend (+30s):** Adds 30 seconds to `timerEndDate` (reassigns the date). Reschedules the `UNUserNotificationCenter` notification to the new end date.

**Skip Rest:** Immediately dismisses overlay. Cancels the pending `UNUserNotificationCenter` notification by identifier.

### SessionSummaryView — Completion Screen

**Trigger:** Last set of last exercise is confirmed (checkmark tap). Session `completedAt` written to CoreData. Summary view replaces the card area (or NavigationStack push — executor's discretion on transition, but NOT a sheet).

**Layout (centered, scrollable if content overflows):**

```
VStack(spacing: 32):
  Spacer().frame(height: 48)  — 2xl breathing room
  Image(systemName: "checkmark.circle.fill")
    .font(.system(size: 72))
    .foregroundStyle(Color("AccentColor"))
  Text("Great work.")         — .title semibold (Display role, 28pt)
  Text("[Day label] complete") — .subheadline regular, .secondary
  Spacer().frame(height: 8)   — sm
  HStack(spacing: 32):        — stat pills in a row
    StatCell(label: "Exercises", value: "\(totalExercises)")
    StatCell(label: "Sets", value: "\(totalSets)")
    StatCell(label: "Reps", value: "\(totalReps)")
  StatCell(label: "Duration", value: "[M]m [S]s")
  Spacer()
  Button("Done")              — .borderedProminent, full width, 52pt height, md margins
```

**StatCell pattern:** `VStack(spacing: 4)` with value (`.title2` semibold) above label (`.subheadline` regular, `.secondary`).

**Duration format:** "42m 07s" — minutes and zero-padded seconds. If under 1 minute: "0m [SS]s".

**Done action:** Pops session NavigationStack back to TrainView. No difficulty rating (Phase 8 scope — CONTEXT.md Deferred).

### Sync Failure Banner

**Trigger:** `syncBannerVisible == true` in `SessionSyncService` (after 3 failed sync retries).

**Layout:** Compact horizontal banner anchored to bottom of `SessionView` (above the tab bar area, which is hidden during session). `HStack` with `exclamationmark.triangle` SF Symbol (`.subheadline`) + text "Couldn't sync your session. Will retry." (`.subheadline` regular). Background: `Color("CardBackground")` with 1pt `.tertiaryLabel` border. Padding: `sm` (8pt) vertical, `md` (16pt) horizontal. Corner radius: 8pt.

**Dismissal:** Auto-hides when sync succeeds on next reconnect attempt. Not user-dismissable (it resolves itself).

## Accessibility Contract

- All interactive elements have `.accessibilityLabel` set.
- Stepper minus button: `.accessibilityLabel("Decrease reps")` + `.accessibilityHint("Current: \(reps) reps")`.
- Stepper plus button: `.accessibilityLabel("Increase reps")` + `.accessibilityHint("Current: \(reps) reps")`.
- Rep count (tappable for number pad): `.accessibilityLabel("\(reps) reps, tap to edit")`.
- Checkmark button (incomplete): `.accessibilityLabel("Mark set \(setNumber) complete")`.
- Checkmark button (completed): `.accessibilityLabel("Set \(setNumber) complete")` + `.accessibilityAddTraits(.isSelected)`.
- Rest timer circular ring: `.accessibilityLabel("Rest timer, \(Int(remaining)) seconds remaining")`.
- Skip Rest button: `.accessibilityLabel("Skip rest, go to next set")`.
- +30s button: `.accessibilityLabel("Add 30 seconds to rest")`.
- Progress bar: `.accessibilityLabel("Exercise \(current) of \(total)")`.
- Session summary checkmark: `.accessibilityLabel("Session complete")`.
- Summary stat cells: `.accessibilityElement(children: .combine)` — reads as "42 Exercises" etc.
- Minimum touch target: 44pt × 44pt on all tappable elements. Stepper buttons and checkmarks use `.contentShape(Rectangle())`.
- Dynamic Type: all text (except rest timer countdown — 64pt fixed) uses semantic SwiftUI font tokens.
- Color contrast: accent `#FF6B35` on `#0F0F0F` = 4.6:1 (WCAG AA). White icon on accent fill = 4.6:1 (WCAG AA).
- Reduce Motion: card transition uses `.animation(.spring(...))` — if `.accessibilityReduceMotion` is enabled, use `.animation(.easeInOut(duration: 0.15))` instead of spring. Use `@Environment(\.accessibilityReduceMotion)` to detect.
