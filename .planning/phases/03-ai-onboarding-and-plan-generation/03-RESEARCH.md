## Summary

Phase 3 delivers three interconnected systems: a SwiftUI guided onboarding card flow, an SSE-streaming plan generation pipeline through a Supabase Edge Function, and a plan preview screen with regeneration capability. The critical technical challenge is the streaming pipeline — iOS client connects to a Deno Edge Function via URLSession bytes stream, the Edge Function proxies OpenAI GPT-4o with streaming enabled, and the client renders partial JSON tokens progressively.

The onboarding UI is straightforward SwiftUI — a custom card container with an integer step index drives `@Observable` ViewModel state. The right primitive is a ZStack or programmatic scroll position (iOS 17) rather than TabView, because chip-tap auto-advance requires programmatic navigation control and the design calls for custom progress indicators not standard page dots.

The most important pitfall for this phase is the known Supabase Swift SDK issue with `invokeWithStreamedResponse` not forwarding the user's auth JWT. The workaround is to build the URLRequest manually, attach the session access token as `Authorization: Bearer <token>`, and call `URLSession.shared.bytes(for:)` directly — bypassing the SDK's streaming invoke path. This is a documented GitHub issue (#634, January 2025) with the manual URLRequest workaround being the community consensus approach.

**Primary recommendation:** Build the streaming SSE client as a thin URLSession wrapper over a manual URLRequest (not the Supabase Swift SDK's invoke stream path), design the OpenAI JSON schema with `additionalProperties: false` and all fields `required` (Structured Outputs constraints), and use CoreData for plan persistence with Supabase as the source of truth.

### Pattern 1: OnboardingViewModel Step Management

**What:** Single ViewModel owns all onboarding state; step index is the source of truth for which card is displayed. Answers accumulate in a typed struct. Auto-advance on single-select chip tap; explicit "Continue" on multi-select.

**When to use:** Any linear wizard flow with programmatic advance logic.

```swift
// [ASSUMED] — pattern follows Phase 1 established conventions
@Observable
@MainActor
final class OnboardingViewModel {
    // Step state
    var currentStep: Int = 0  // 0-indexed; 0=Goal, 1=Fitness, 2=Days, 3=Equipment, 4=Injuries
    var showQuitConfirmation: Bool = false

    // Answers
    var selectedGoal: String? = nil
    var selectedFitnessLevel: String? = nil
    var selectedDaysPerWeek: Int? = nil
    var selectedEquipment: Set<String> = []
    var injuriesText: String = ""

    func selectGoal(_ goal: String) {
        selectedGoal = goal
        advance()  // auto-advance on single-select
    }

    func advance() {
        guard currentStep < 4 else { return }
        withAnimation(.spring(duration: 0.35)) {
            currentStep += 1
        }
    }

    func goBack() {
        guard currentStep > 0 else { return }
        withAnimation(.spring(duration: 0.35)) {
            currentStep -= 1
        }
    }
}
```

### Pattern 2: SSE Streaming Client (Manual URLSession)

**What:** Bypass `supabase.functions.invoke` streaming path (auth bug #634). Build URLRequest manually with `Authorization: Bearer` header. Use `URLSession.shared.bytes(for:)` async sequence to process SSE lines.

**When to use:** Any SSE streaming call to Supabase Edge Functions from iOS until SDK issue is resolved.

```swift
// [ASSUMED] — derived from URLSession async bytes API (iOS 15+) and SSE spec
// Source pattern: https://zachwaugh.com/posts/streaming-messages-chatgpt-swift-asyncsequence
final class PlanSSEClient {
    func streamPlan(
        userProfile: UserProfile,
        session: Session
    ) -> AsyncThrowingStream<String, Error> {
        AsyncThrowingStream { continuation in
            Task {
                var request = URLRequest(
                    url: URL(string: "\(supabaseURL)/functions/v1/generate-plan")!
                )
                request.httpMethod = "POST"
                request.setValue("Bearer \(session.accessToken)", forHTTPHeaderField: "Authorization")
                request.setValue("application/json", forHTTPHeaderField: "Content-Type")
                request.httpBody = try? JSONEncoder().encode(userProfile)

                let (asyncBytes, _) = try await URLSession.shared.bytes(for: request)
                for try await line in asyncBytes.lines {
                    if line.hasPrefix("data: ") {
                        let data = String(line.dropFirst(6))
                        if data == "[DONE]" { break }
                        continuation.yield(data)
                    }
                }
                continuation.finish()
            }
        }
    }
}
```

### Pattern 3: OpenAI Structured Outputs JSON Schema for Workout Plan

**What:** Strict JSON schema with `additionalProperties: false` and all fields `required`. No `oneOf`, `anyOf`, or optional object keys — these are unsupported by Structured Outputs strict mode.

**When to use:** Plan generation call from the Deno Edge Function.

```typescript
// [ASSUMED] — derived from OpenAI Structured Outputs docs constraints
// Source: https://platform.openai.com/docs/guides/structured-outputs
const planSchema = {
  type: "object",
  properties: {
    plan_name: { type: "string" },
    goal_summary: { type: "string" },
    weekly_days: {
      type: "array",
      items: {
        type: "object",
        properties: {
          day_label: { type: "string" },      // e.g. "Day 1 - Monday"
          session_name: { type: "string" },    // e.g. "Upper Body Strength"
          exercises: {
            type: "array",
            items: {
              type: "object",
              properties: {
                exercise_name: { type: "string" },
                sets: { type: "integer" },
                reps: { type: "string" },      // string allows "8-12" ranges
                rest_seconds: { type: "integer" },
                rationale: { type: "string" }  // AIPL-02: why this exercise
              },
              required: ["exercise_name", "sets", "reps", "rest_seconds", "rationale"],
              additionalProperties: false
            }
          }
        },
        required: ["day_label", "session_name", "exercises"],
        additionalProperties: false
      }
    }
  },
  required: ["plan_name", "goal_summary", "weekly_days"],
  additionalProperties: false
};
```

### Pattern 4: Supabase Edge Function — Deno SSE Proxy

**What:** Edge Function receives user profile, constructs system prompt, calls OpenAI with `stream: true`, and forwards SSE tokens directly to the client response stream.

**When to use:** This is the only pattern for OpenAI calls — never call OpenAI from iOS client directly.

```typescript
// [ASSUMED] — derived from Supabase Edge Function SSE streaming patterns
// Source: https://github.com/orgs/supabase/discussions/13124
import { serve } from "https://deno.land/std@0.168.0/http/server.ts"

serve(async (req) => {
  const profile = await req.json()

  const systemPrompt = `You are a professional fitness coach. Generate a personalized workout plan.
User profile:
- Goal: ${profile.goal}
- Fitness Level: ${profile.fitness_level}
- Days per week: ${profile.days_per_week}
- Available equipment: ${profile.equipment.join(", ")}
${profile.injuries ? `- Areas to avoid: ${profile.injuries}` : ""}

Generate a ${profile.days_per_week}-day weekly plan. For each exercise, provide a rationale explaining why it was chosen for this user's specific goal and equipment.`

  const openAIResponse = await fetch("https://api.openai.com/v1/chat/completions", {
    method: "POST",
    headers: {
      "Authorization": `Bearer ${Deno.env.get("OPENAI_API_KEY")}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({
      model: "gpt-4o-2024-08-06",  // minimum version for Structured Outputs
      stream: true,
      response_format: {
        type: "json_schema",
        json_schema: {
          name: "workout_plan",
          strict: true,
          schema: planSchema  // defined separately
        }
      },
      messages: [
        { role: "system", content: systemPrompt },
        { role: "user", content: "Generate my personalized weekly workout plan." }
      ]
    })
  })

  // Forward the SSE stream directly
  return new Response(openAIResponse.body, {
    headers: {
      "Content-Type": "text/event-stream",
      "Cache-Control": "no-cache",
      "Access-Control-Allow-Origin": "*"
    }
  })
})
```

**What:** PostgreSQL table stores the complete plan JSON alongside normalized metadata columns for querying.

```sql
CREATE POLICY "Users can view own plans"
    ON public.workout_plans FOR SELECT
    USING (auth.uid() = user_id);

CREATE POLICY "Users can insert own plans"
    ON public.workout_plans FOR INSERT
    WITH CHECK (auth.uid() = user_id);
```

### Anti-Patterns to Avoid

- **Calling OpenAI from iOS client:** API key extractable from binary. All OpenAI calls go through Supabase Edge Function.
- **Using `supabase.functions.invokeWithStreamedResponse` for auth-sensitive SSE:** Known SDK bug #634 — auth JWT not forwarded. Use manual URLRequest with `Authorization: Bearer`.
- **Storing the workout plan only in memory:** App crash = lost plan. Write to Supabase first, then CoreData. Never display a plan that hasn't been persisted.
- **Using `anyOf` / `oneOf` in Structured Outputs schema:** These keywords are unsupported in strict mode. Use required fields and string types for optional data (empty string vs null workaround: use empty string, handle in display layer).
- **Making `injuries` a nullable JSON field in Structured Outputs:** Nullable optional fields are not directly supported in strict mode schema. Use a string with an empty string sentinel ("") or include it always required with an empty string default.
- **TabView + PageTabViewStyle for this flow:** Chip-tap auto-advance conflicts with TabView's drag-to-switch gesture; custom ZStack with `.transition(.asymmetric)` gives programmatic control.
- **Regeneration count stored server-side:** Unnecessary for onboarding-phase cap. Local ViewModel state is sufficient and avoids an extra API call on each regeneration check.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| JSON schema enforcement on AI output | Custom JSON parsing with regex / fallback | OpenAI Structured Outputs (`response_format: json_schema`, `strict: true`) | Constrained decoding guarantees 100% schema adherence at the token level; custom parsing always has edge cases |
| SSE line parsing | Custom byte buffer / delimiter parser | `URLSession.bytes(for:).lines` async sequence | Apple's `lines` property handles `\r\n`, `\n`, `\r` line endings and buffering correctly |
| Auth token storage | UserDefaults, in-memory | KeychainAccess (already installed) → read `supabase.auth.session.accessToken` | Tokens in UserDefaults appear in plaintext backups |
| OpenAI API proxy | Custom backend server | Supabase Edge Function (Deno) | Already in stack; zero-config deployment with `supabase functions deploy` |
| Plan persistence across launches | In-memory plan state | CoreData `CDWorkoutPlan` entity | Crash safety; required for offline workout session access in Phase 4 |

**Key insight:** The SSE streaming pipeline looks complex but is actually 3 well-understood primitives composed together: `URLSession.bytes(for:)` on iOS, `ReadableStream` passthrough in Deno, and OpenAI's native SSE format. Each piece has official documentation and established patterns. The only non-obvious part is the auth header workaround.

## Common Pitfalls

### Pitfall 1: Supabase Swift SDK Streaming Drops Auth Token
**What goes wrong:** Calling `supabase.functions.invokeWithStreamedResponse(...)` causes the Edge Function to receive an unauthenticated request. `auth.uid()` returns null server-side, breaking any RLS policy or user-scoped logic.
**Why it happens:** SDK bug #634 (reported January 2025) — the streaming invoke path uses a different URLSession configuration that does not attach the session JWT.
**How to avoid:** Build the URLRequest manually. Read `supabase.auth.currentSession?.accessToken` and set `Authorization: Bearer <token>` header explicitly. Use `URLSession.shared.bytes(for: request)`.
**Warning signs:** Edge Function logs show anonymous role; plan write fails due to RLS policy; `auth.uid()` is null in Edge Function logs.

### Pitfall 2: Structured Outputs Schema with Optional / Nullable Fields
**What goes wrong:** Including nullable types (`{ "type": ["string", "null"] }`) or omitting a field from `required` causes a 400 API error: "schema validation failed" in strict mode.
**Why it happens:** OpenAI's strict Structured Outputs constrains the schema to a subset of JSON Schema. Every field must be in `required`, and `additionalProperties` must be `false` at every object level.
**How to avoid:** Make every field required. For truly optional data (e.g., `injuries`), use a required string field with an empty string sentinel ("") instead of null.
**Warning signs:** OpenAI API returns 400 with schema validation error; error message mentions "required" or "additionalProperties".

### Pitfall 3: Streaming JSON Partial Parse Crash
**What goes wrong:** Trying to parse partial JSON tokens as complete JSON while streaming causes a decode crash. The plan schema is a large nested object — partial tokens are not valid JSON until the stream is complete.
**Why it happens:** With Structured Outputs + streaming, tokens arrive as partial JSON fragments. The model streams valid JSON only when the full response is assembled.
**How to avoid:** During streaming, display the raw token text progressively (character append to a text buffer) for the loading animation. Only parse the final assembled string as `WorkoutPlan` Codable when the stream closes (SSE `[DONE]` event received).
**Warning signs:** `JSONDecoder` throws during streaming; plan object is nil even though tokens arrived.

### Pitfall 4: `onboarding_completed` Flag Race Condition
**What goes wrong:** Setting `onboarding_completed = true` in `profiles` before the plan has been written to `workout_plans` causes the app to route to `MainTabView` with no plan data, showing an empty home screen.
**Why it happens:** If profile update and plan write are done concurrently, the flag can flip before plan storage completes.
**How to avoid:** Strict ordering: (1) write plan to Supabase `workout_plans`, (2) write plan to CoreData, (3) UPSERT `profiles.onboarding_completed = true`, (4) update `AppState.onboardingCompleted`. Use sequential `await` calls, not concurrent `async let`.
**Warning signs:** Home view shows empty plan state for a brief moment after onboarding; or always shows empty after a crash mid-write.

### Pitfall 5: iOS URLSession and Background Task Expiration
**What goes wrong:** On slow networks, plan generation via SSE may take 15–30+ seconds. If the app moves to background mid-stream (user switches apps), iOS may suspend the URLSession task, silently cutting the stream.
**Why it happens:** Regular `URLSession.shared` tasks are suspended when the app backgrounds.
**How to avoid:** Wrap the plan generation call in a `Task` that begins a background task with `UIApplication.shared.beginBackgroundTask`. Alert the user if backgrounded mid-generation. Alternatively, accept the risk — plan generation from onboarding is a foreground-only UX.
**Warning signs:** Stream appears to hang; `URLError.cancelled` thrown without user action.

### Pitfall 6: Regeneration Counter Not Surviving ViewModel Recreation
**What goes wrong:** If the user backgrounds and returns, and the ViewModel is recreated, the regeneration counter resets to 3, allowing unlimited regenerations.
**Why it happens:** In-memory counter on `PlanPreviewViewModel` does not persist across view lifecycle.
**How to avoid:** Store the regeneration counter in `@AppStorage("regenCountUsed")` or pass it through the AppState. Since it is onboarding-only and resets after onboarding completes, `@AppStorage` is sufficient.
**Warning signs:** User gets more than 3 regenerations by backgrounding the app.

## State of the Art

| Old Approach | Current Approach | When Changed | Impact |
|--------------|------------------|--------------|--------|
| JSON Mode (`response_format: { type: "json_object" }`) | Structured Outputs (`json_schema` + `strict: true`) | August 2024 (gpt-4o-2024-08-06) | Schema is now enforced at token level — 100% guarantee vs best-effort |
| Combine for async streaming | `AsyncThrowingStream` + `URLSession.bytes` | Swift 5.5 / iOS 15 | Structured concurrency is the Swift 6 idiom; no Combine for new code |
| SwiftData for local persistence | CoreData | Phase 1 decision | SwiftData has iOS 18 memory issues; CoreData is stable for workout history volume |
| CocoaPods / Carthage | Swift Package Manager | Xcode 12+ | SPM is the standard; project uses SPM only |

**Deprecated/outdated:**
- JSON Mode (`type: "json_object"`): Works but schema compliance is not guaranteed. Do not use for plan generation where exercise schema integrity is critical.
- `TabView + PageTabViewStyle` for programmatic onboarding: Works but conflicts with chip-tap auto-advance; use ZStack or programmatic `ScrollPosition` (iOS 17).
- Third-party OpenAI Swift SDKs: Lag behind API releases; custom URLSession client is 100–200 lines and matches project conventions.

## Security Domain

### Applicable ASVS Categories

| ASVS Category | Applies | Standard Control |
|---------------|---------|-----------------|
| V2 Authentication | yes | Supabase Auth JWT; attached as Bearer token on all Edge Function calls |
| V3 Session Management | yes | Supabase handles JWT refresh; `supabase.auth.session` always current token |
| V4 Access Control | yes | Supabase RLS on `profiles` and `workout_plans`; user can only read/write own rows |
| V5 Input Validation | yes | User onboarding answers are chip selections (enumerated values, not free text) — minimal injection risk; `injuries` text field is the only free-text input and goes only into the AI system prompt, not a database query |
| V6 Cryptography | partial | OpenAI API key stored as Supabase Edge Function secret (env var, not hardcoded); never in iOS binary |

### Known Threat Patterns for This Stack

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| OpenAI API key extraction from iOS binary | Information Disclosure | All OpenAI calls proxied through Supabase Edge Function; key never in iOS binary |
| Prompt injection via `injuries` free-text field | Tampering | System prompt wraps user input in a structured slot; OpenAI safety layer provides secondary defense; Structured Outputs constrain output to schema regardless of input |
| Unauthorized plan access (other users' plans) | Elevation of Privilege | RLS policy on `workout_plans` enforces `auth.uid() = user_id` |
| JWT interception on SSE stream | Information Disclosure | HTTPS enforced for all Supabase endpoints; URLSession uses TLS by default |
| Regeneration limit bypass | Elevation of Privilege | Counter in `@AppStorage`; acceptable for onboarding-phase cap; not financial/critical |
