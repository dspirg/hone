# Phase 3 — UI Design Contract

> Visual and interaction contract for Phase 3: AI Onboarding and Plan Generation. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — iOS native (SwiftUI HIG) |
| Preset | not applicable |
| Component library | SwiftUI native views (no third-party component library) |
| Icon library | SF Symbols 5 (system icons bundled with iOS 17+) |
| Font | SF Pro (system default; no custom font) |

**Note:** iOS-only SwiftUI project. shadcn, Tailwind, and web component libraries are not applicable. All design tokens inherit from Phase 1 and Phase 2. Phase 3 extends the established contract for onboarding cards and plan preview screens. (Source: Phase 1 UI-SPEC + Phase 2 UI-SPEC + CONTEXT.md.)

## Spacing Scale

iOS HIG minimum touch target: 44pt. All values in SwiftUI points. Inherited from Phase 1; no new scale values.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-label gaps, chip internal vertical padding |
| sm | 8pt | Between tap chips in a row, gap between progress pill and progress bar |
| md | 16pt | Default horizontal content margin, card body horizontal padding |
| lg | 24pt | Section padding, gap between card heading and chip grid |
| xl | 32pt | Horizontal edge padding on plan preview day card body content |
| 2xl | 48pt | Vertical breathing room above "Start Training" sticky CTA; space above first day card |
| 3xl | 64pt | Top safe area clearance for full-screen onboarding card content |

Exceptions:
- Touch targets: minimum 44pt height on all tappable elements — tap chips, "Continue" button, "Skip" button, "Regenerate plan" button, "Start Training" CTA — iOS HIG requirement.
- Tap chip height: 52pt (larger than Phase 2 filter chips — onboarding chips are primary input controls, not filter accessories; generous tap area improves completion rate).
- Tap chip width: content-driven, minimum 140pt (prevents overly narrow chips on multi-option rows).
- Progress bar height: 3pt — visually thin, not a tappable element; not subject to 44pt minimum.
- Sticky "Start Training" CTA: bottom safe area inset + `md` (16pt) padding above safe area bottom edge; full width with `md` (16pt) horizontal margins.

## Typography

All sizes in SwiftUI points. Font: SF Pro (system default via `.font()` modifier). Dynamic Type required on all text. Inherits Phase 1/2 four-size, two-weight constraint.

| Role | Size | Weight | Line Height | SwiftUI Token |
|------|------|--------|-------------|---------------|
| Body | 17pt | Regular (400) | 1.5 | `.body` |
| Label | 15pt | Regular (400) | 1.4 | `.subheadline` |
| Heading | 22pt | Semibold (600) | 1.2 | `.title2` |
| Display | 28pt | Semibold (600) | 1.1 | `.title` |

Phase 3 role assignments (no new sizes or weights introduced):

- Onboarding card question heading ("What's your main goal?"): `.title` (28pt, semibold 600) — large and prominent, reduces cognitive load per card.
- Tap chip label: `.body` (17pt, regular 400) — readable at a glance, comfortable tap target labeling.
- Progress pill text ("2 of 5"): `.subheadline` (15pt, regular 400) — subordinate to card content.
- "Skip" link: `.subheadline` (15pt, regular 400), accent color — visually distinct without competing with chips.
- "Continue" / "Save & Continue" button label: `.body` (17pt, semibold 600) — primary action on multi-select cards.
- Loading phase copy ("Analyzing your goals…"): `.title` (28pt, semibold 600) — sole content on loading screen; must feel intentional.
- Plan name heading: `.title` (28pt, semibold 600) — e.g. "Your 4-Day Strength Plan".
- Goal summary subheading: `.body` (17pt, regular 400), `.secondary` color — one sentence below plan name.
- Day card session name: `.title2` (22pt, semibold 600) — e.g. "Day 1 — Upper Body Strength".
- Exercise name in day card row: `.subheadline` (15pt, semibold 600) — pulls from Label size with Heading weight.
- Exercise sets/reps/rest line: `.subheadline` (15pt, regular 400), `.secondary` color — subordinate to exercise name.
- AI rationale ("Why: builds posterior chain…"): `.subheadline` (15pt, regular 400), `.tertiaryLabel` color — visually quietest text in the hierarchy; coach note annotation.
- Regeneration counter label ("2 regenerations remaining"): `.subheadline` (15pt, regular 400), `.secondary` color.
- Error body copy: `.body` (17pt, regular 400) — standard body role.

**Constraints (inherited from Phase 1/2):**
- Maximum 4 sizes: 15pt, 17pt, 22pt, 28pt. No additional sizes.
- Maximum 2 weights: Regular (400) and Semibold (600). No medium, bold, or italic.
- All text must use SwiftUI semantic font tokens — never `.system(size: N)` — so iOS accessibility Dynamic Type scaling works automatically.

## Color

Phase 3 inherits Phase 1/2 dark-mode-first fitness aesthetic. One new semantic state introduced: streaming/loading highlight.

| Role | Dark Mode | Light Mode | Usage |
|------|-----------|------------|-------|
| Dominant (60%) | `#0F0F0F` (near-black) | `#F5F5F5` (near-white) | Full-screen onboarding card background, plan preview background, loading screen background |
| Secondary (30%) | `#1C1C1E` (system grouped bg) | `#FFFFFF` (white) | Unselected tap chip fill, day card fill on plan preview, exercise row background |
| Accent (10%) | `#FF6B35` (energetic orange) | `#FF6B35` (same) | Selected tap chip fill + border; active progress bar fill; "Continue" button fill; "Start Training" CTA fill |
| Destructive | `#FF3B30` (iOS system red) | `#FF3B30` (same) | "Quit setup?" confirmation sheet — destructive "Quit" button only |

**SwiftUI semantic mappings (inherited):**
- Dominant: `.systemBackground` / `Color("AppBackground")`
- Secondary: `.secondarySystemBackground` / `Color("CardBackground")`
- Accent: `Color("AccentColor")` — app accent color in Assets.xcassets
- Destructive: `Color.red` / `.systemRed`

Accent reserved for (Phase 3 additions):
1. Selected tap chip — fill `Color("AccentColor")` at 100% opacity; chip label text `.white`
2. Active progress bar fill — `Color("AccentColor")` at full opacity on the 3pt progress bar track
3. "Continue" button on Equipment card (multi-select) — full-width, accent fill, `lg` (24pt) vertical padding
4. "Save & Continue" button on Injuries card (optional) — same styling as "Continue"
5. "Start Training" CTA — sticky bottom button, full width, accent fill, 52pt height, 12pt corner radius
6. "Skip" link text on Injuries card — accent color, no fill, no border
7. (Inherited) Active tab bar item icon + label tint

Accent is NOT used for: unselected chip fills, chip borders on unselected state, day card backgrounds, exercise row text, AI rationale text, progress pill background, loading screen body text, "Regenerate plan" button (secondary style — see below), or back chevron.

**Unselected tap chip:** `Color("CardBackground")` fill, Label-color text, 1pt border in `.tertiaryLabel` color, 12pt corner radius.
**Selected tap chip:** `Color("AccentColor")` fill, `.white` text, no border, 12pt corner radius.
**"Regenerate plan" button:** secondary style — `Color("CardBackground")` fill, accent-colored label text, 1pt accent border. Disabled state: `.quaternaryLabel` fill, `.tertiaryLabel` text, no border.
**Progress bar track (background):** `.tertiaryLabel` color fill at 20% opacity, 3pt height, full width.
**Loading screen cycling text:** `.primary` color (full opacity) fading in/out via `.opacity` animation.

## Interaction Contracts

### OnboardingView — Container

**Layout:**
- Full-screen dark surface (`Color("AppBackground")`).
- Top: `OnboardingProgressView` — "2 of 5" pill (centered) + 3pt progress bar (full width, `md` horizontal inset). Total height: 36pt. Top padding: `md` (16pt) below safe area top.
- Below progress: ZStack containing the active card view. Cards fill remaining vertical space between progress bar and bottom safe area.
- Back chevron: system `.chevronLeft` icon, leading top corner, `md` (16pt) leading inset, 44pt hit area. Hidden on Step 0 (no card to go back to).

**Card transition animation:**
- Forward (chip auto-advance or "Continue" tap): new card slides in from trailing edge, old card exits to leading edge — `.asymmetric(insertion: .move(edge: .trailing), removal: .move(edge: .leading))` with `.spring(duration: 0.35, bounce: 0.1)`.
- Backward (back chevron tap or swipe): new card slides in from leading edge, old card exits to trailing edge — reversed asymmetric transition, same spring.
- `withAnimation` wraps `currentStep` increment/decrement in `OnboardingViewModel`.

**Exit behavior (mid-flow dismiss):**
- If user attempts system dismiss gesture or back chevron on Step 0: show `"Quit setup?"` confirmation.
- Confirmation copy: title "Quit setup?", message "You'll lose your progress and won't get your personalized plan.", destructive button "Quit", cancel button "Continue Setup".
- "Quit": dismisses `.fullScreenCover`, leaves `onboarding_completed = false` in AppState.
- "Continue Setup": dismisses the sheet, resumes onboarding at current step.

### OnboardingProgressView

- "N of 5" pill: `Text("2 of 5")` in `.subheadline` regular, white text on `Color("CardBackground")` background, 8pt horizontal padding, 4pt vertical padding, `.capsule()` shape. Centered horizontally.
- `sm` (8pt) gap between pill and progress bar.
- Progress bar: `GeometryReader` or `ProgressView(value:)` — full width minus `md` (16pt) leading/trailing. Track: `.tertiaryLabel` at 20% opacity, 3pt height, `.capsule()`. Fill: `Color("AccentColor")`, animated via `.animation(.spring(duration: 0.4))` on step change.

### GoalCardView — Step 0

**Layout (top to bottom, within card vertical space):**
1. `Spacer()` flexible top — pushes content toward vertical center-upper third.
2. Card question heading: "What's your main goal?" — `.title` (28pt, semibold), `.primary` color, `md` (16pt) horizontal inset, center-aligned. Line limit: 2.
3. `lg` (24pt) gap.
4. Chip grid: `LazyVGrid(columns: [GridItem(.flexible()), GridItem(.flexible())], spacing: 12)` — 2-column grid, `md` (16pt) horizontal inset.
5. `Spacer()` flexible bottom.

**Chips (4 options, 2×2 grid):**
- "Build Muscle"
- "Lose Fat"
- "Get Fitter"
- "Athletic Performance"

**Chip appearance:** 52pt height, full column width, 12pt corner radius, 1pt border.
**Interaction:** Single-select. Tap any chip → immediate visual selection (accent fill) → `withAnimation(.spring(duration: 0.35)) { currentStep += 1 }` after a 120ms delay (lets user perceive the selection before advancing).
**No "Continue" button** — auto-advance on tap.

### FitnessLevelCardView — Step 1

**Layout:** Same structure as GoalCardView.
**Question:** "What's your fitness level?"
**Chips (3 options, single column — centered):**
- "Beginner"
- "Intermediate"
- "Advanced"

**Layout for 3 chips:** Single-column `VStack(spacing: 12)`, horizontally centered, each chip full-width minus `md` (16pt) × 2 horizontal insets.
**Interaction:** Single-select, auto-advance on tap (same 120ms delay before step advance).

### DaysPerWeekCardView — Step 2

**Layout:** Same structure as GoalCardView.
**Question:** "How many days per week can you train?"
**Chips (4 options, 2×2 grid):**
- "2 days"
- "3 days"
- "4 days"
- "5 days"

**Interaction:** Single-select, auto-advance on tap (same 120ms delay).

### EquipmentCardView — Step 3

**Layout:**
1. `Spacer()` flexible top.
2. Card question heading: "What equipment do you have access to?" — same heading style.
3. `sm` (8pt) gap.
4. Sub-label: "Select all that apply." — `.subheadline` (15pt, regular), `.secondary` color, same horizontal inset, center-aligned.
5. `lg` (24pt) gap.
6. Chip grid: `LazyVGrid(columns: [GridItem(.flexible()), GridItem(.flexible())], spacing: 12)`, `md` (16pt) horizontal inset.
7. `lg` (24pt) gap.
8. "Continue" button: full-width minus `md` (16pt) × 2, 52pt height, 12pt corner radius, accent fill when at least 1 chip selected; `.quaternaryLabel` fill when 0 chips selected (disabled state). Label: `.body` (17pt, semibold).
9. `Spacer()` flexible bottom (smaller weight than top spacer — CTA biased toward lower third).

**Chips (5 options, 2×2 grid + 1 full-width last row):**
- "No equipment" (full-width, 2-column span — exclusive option)
- "Dumbbells"
- "Barbell"
- "Pull-up bar"
- "Full gym"

**Multi-select logic:** "No equipment" is mutually exclusive — selecting it deselects all others; selecting any equipment chip deselects "No equipment". Minimum 1 selection required before "Continue" is enabled.

**Interaction:** Multi-select chip toggles on tap. "Continue" button tap → advance to Step 4 (InjuriesCardView).

### InjuriesCardView — Step 4 (Optional)

**Layout:**
1. `Spacer()` flexible top.
2. "Skip" link: top-right corner of card area, `md` (16pt) trailing inset, `sm` (8pt) top inset from progress bar. `.subheadline` (15pt, regular), accent color. Tap: skip injuries card → trigger profile UPSERT + plan generation.
3. Card question heading: "Any areas to avoid?" — same heading style.
4. `sm` (8pt) gap.
5. Sub-label: "Optional — helps the AI protect you from aggravating existing injuries." — `.subheadline` (15pt, regular), `.secondary` color, center-aligned.
6. `lg` (24pt) gap.
7. Text field: `TextField("e.g. lower back, left knee", text: $injuriesText)` — multi-line via `.lineLimit(3, reservesSpace: true)`, `md` (16pt) internal padding, `Color("CardBackground")` fill, 1pt `.tertiaryLabel` border, 12pt corner radius.
8. `lg` (24pt) gap.
9. "Save & Continue" button: same styling as Equipment "Continue" button. Always enabled (empty text is valid — user can proceed with no injuries listed). Tap → profile UPSERT + plan generation.
10. `Spacer()` flexible bottom.

**Skip behavior:** Tap "Skip" clears `injuriesText` to empty string, triggers profile UPSERT with `injuries: ""`, then starts plan generation (navigates to loading screen).
**"Save & Continue" behavior:** Same — writes `injuriesText` (or `""`) to profile UPSERT, then starts plan generation.

### PlanGenerationLoadingView

**Layout (full screen, replaces card content within OnboardingView container):**
1. `Spacer()` flexible (top third).
2. Animated loading indicator: custom pulsing ring — three concentric `Circle` strokes in accent color at 100%, 60%, 30% opacity, each rotating with `.rotationEffect` + `.animation(.linear(duration: 2).repeatForever(autoreverses: false))`. Outer ring: 80pt diameter, 3pt stroke. Middle ring: 56pt, 2pt stroke (counter-rotate). Inner ring: 32pt, 2pt stroke (same rotation as outer). — (Claude's Discretion for animation style, within discretion scope from CONTEXT.md.)
3. `lg` (24pt) gap.
4. Cycling phase text: `Text(currentPhaseText)` — `.title` (28pt, semibold), `.primary` color, center-aligned, `md` (16pt) horizontal inset. Transitions between phases via `.transition(.opacity)` + `.animation(.easeInOut(duration: 0.4))`. 3-second cycle timer, 3 phases:
   - "Analyzing your goals…"
   - "Building your schedule…"
   - "Selecting your exercises…"
5. `Spacer()` flexible (bottom third — larger than top).

**No progress bar** — SSE provides no progress signal. Loading state persists until SSE `[DONE]` event or error.
**No cancel button** — plan generation is fast (5–15s typical). User cannot cancel mid-stream.
**Error overlay (network drop, D-17):** Replaces loading content with centered VStack: `wifi.slash` SF Symbol (48pt, `.secondary`) + "Check your connection" heading (`.title2`, semibold) + "Make sure you're connected to the internet, then try again." body (`.body`, regular, `.secondary` color, center-aligned) + "Try Again" button (accent fill, 52pt height, 12pt corner radius). No back navigation from error state — "Try Again" retries the SSE call.
**Silent retry (D-16):** First failure retries automatically. Loading animation continues. Error overlay shown only if second attempt also fails.

### PlanPreviewView

**Layout (within OnboardingView container, progress bar hidden — replaced by plan header):**

**Header area (sticky, above scroll):**
1. Plan name: `Text(plan.planName)` — `.title` (28pt, semibold), `md` (16pt) top padding below safe area, `md` (16pt) horizontal inset.
2. Goal summary: `Text(plan.goalSummary)` — `.body` (17pt, regular), `.secondary` color, `sm` (8pt) below plan name, `md` (16pt) horizontal inset. Line limit: 3.
3. `sm` (8pt) gap.
4. Inline row: regeneration counter label + "Regenerate plan" button — `HStack(alignment: .center)`.
   - Counter label: "2 regenerations remaining" — `.subheadline` (15pt, regular), `.secondary` color. Updates as regenerations are used. Hidden when counter reaches 0.
   - Disabled label (when cap reached): "Save regenerations for the app" — `.subheadline` (15pt, regular), `.tertiaryLabel` color.
   - "Regenerate plan" button: `Color("CardBackground")` fill, accent-colored `.subheadline` (15pt, regular) label, 1pt accent border, 8pt horizontal padding, 32pt height, `.capsule()` shape. Leading icon: `arrow.clockwise` SF Symbol at 13pt. Disabled state: `.quaternaryLabel` fill, `.tertiaryLabel` text, no border.
5. `sm` (8pt) gap.
6. `Divider()`.

**Scrollable content (below header):**
- `ScrollView(.vertical)` containing `VStack(spacing: 16)` of day cards.
- `2xl` (48pt) top padding inside scroll content.
- Bottom padding: 100pt (clears sticky CTA).

**Day card (`WorkoutDayCardView`):**
- `Color("CardBackground")` fill, 16pt corner radius, `md` (16pt) horizontal inset (relative to scroll view edges), no explicit shadow (consistent with Phase 2 card styling — flat).
- Card header: day session name (e.g. "Day 1 — Upper Body Strength") — `.title2` (22pt, semibold), `md` (16pt) top/horizontal padding inside card.
- `sm` (8pt) gap below session name.
- `Divider()` inside card.
- Exercise rows: `VStack(spacing: 0)` of `ExerciseRowView` items separated by `Divider()` (inset 16pt leading).

**Exercise row (`ExerciseRowView`):**
- Vertical padding: `sm` (8pt) top, `sm` (8pt) bottom. Leading/trailing: `md` (16pt) inside card.
- Exercise name: `.subheadline` (15pt, semibold) — top line.
- Sets/reps/rest line: `Text("\(exercise.sets) sets × \(exercise.reps) — \(exercise.restSeconds)s rest")` — `.subheadline` (15pt, regular), `.secondary` color — second line, `xs` (4pt) below name.
- AI rationale: `Text("Why: \(exercise.rationale)")` — `.subheadline` (15pt, regular), `.tertiaryLabel` color — third line, `xs` (4pt) below sets line. `sf` prefix icon: `quote.opening` SF Symbol at 11pt, `.tertiaryLabel` color — inline leading the rationale text via `Label` or `HStack`.
- Tap behavior: none (rows are read-only in Phase 3; exercise detail navigation is Phase 4).

**Sticky "Start Training" CTA:**
- `VStack` overlay at bottom of `ZStack` wrapping ScrollView + CTA. Background: `Color("AppBackground")` with `sm` (8pt) top inset.
- Button: "Start Training" — full width minus `md` (16pt) × 2 horizontal margins, 52pt height, 12pt corner radius, `Color("AccentColor")` fill, `.white` label text, `.body` (17pt, semibold).
- Bottom padding: safe area bottom inset.
- Action: triggers paywall (Phase 7 integration point). In Phase 3, records `onboarding_completed = true` in `profiles` and routes to `MainTabView` (paywall is a Phase 7 concern).

**Streaming state (regeneration in progress):**
- Day cards and exercise rows display partial content as tokens arrive. Exercise rows that have not yet received data show a placeholder: `Color("CardBackground")` rounded rect, 12pt height, 60% screen width, `.secondary` opacity at 40% — skeleton shimmer via `opacity` animation cycling 40%–70% every 0.8s.
- Plan name and goal summary animate from empty to content as tokens accumulate.
- "Regenerate plan" button is disabled and shows `ProgressView` replacing its icon during active regeneration stream.
- "Start Training" CTA is disabled (`.quaternaryLabel` fill, `.tertiaryLabel` text) while streaming is in progress.

## Accessibility Contract

- All interactive elements have `.accessibilityLabel` set.
- Tap chips: `.accessibilityLabel("[Option text]")` + `.accessibilityAddTraits(.isButton)` + `.accessibilityValue(isSelected ? "selected" : "not selected")`. Auto-advance chips add `.accessibilityHint("Selects this option and advances to the next question.")`.
- Progress indicator: `.accessibilityLabel("Step \(current) of 5")` on the progress pill. Progress bar: `.accessibilityHidden(true)` (redundant with pill label).
- Back chevron button: `.accessibilityLabel("Go back")`.
- "Skip" link: `.accessibilityLabel("Skip — no injuries to add")`.
- "Continue" / "Save & Continue" buttons: standard label, `.accessibilityHint("Proceeds to the next step.")`.
- Loading screen: the cycling text is announced once per phase change via `.accessibilityAnnouncement` when phase text changes. Animation ring: `.accessibilityHidden(true)`.
- Plan name and goal summary: standard readable — no custom labels needed.
- Day card session name: `.accessibilityAddTraits(.isHeader)`.
- Exercise row: `.accessibilityElement(children: .combine)` on the VStack — VoiceOver reads exercise name + sets/reps/rest + rationale as a single accessible element. Label: "[Exercise name], [sets] sets, [reps] reps, [rest] seconds rest. Why: [rationale]".
- "Regenerate plan" button: `.accessibilityLabel("Regenerate plan")` + `.accessibilityValue("\(regenCount) regenerations remaining")`. Disabled state: `.accessibilityHint("Regeneration limit reached.")`.
- "Start Training" CTA: `.accessibilityLabel("Start Training")` + `.accessibilityHint("Proceeds to subscription options.")`. Disabled during streaming: `.accessibilityHint("Plan is still loading. Wait for the plan to finish before proceeding.")`.
- Minimum touch target: 44pt × 44pt on all tappable elements. Chips use `.contentShape(Rectangle())` to extend hit area.
- Dynamic Type: all text uses semantic SwiftUI font tokens — never `.system(size: N)`.
