## Spacing Scale

iOS HIG minimum touch target: 44pt. All values in SwiftUI points.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4pt | Icon-to-label gaps, chip internal horizontal padding (left/right of text) |
| sm | 8pt | Between filter chips, between muscle-group tag pills |
| md | 16pt | Default horizontal content margin, row vertical padding |
| lg | 24pt | Section header padding, video player bottom margin to content |
| xl | 32pt | Horizontal edge padding on detail view body content |
| 2xl | 48pt | Vertical breathing room above first section header in list |
| 3xl | 64pt | Top safe area clearance (full-screen content) |

Exceptions:
- Touch targets: minimum 44pt height for all tappable elements (filter chips, exercise rows, search bar, nav back button) — iOS HIG requirement.
- Filter chip height: 36pt tall (visually compact), padded to 44pt touch target with `.contentShape(Rectangle())` extending the hit area.
- Video player area: ~40% of screen height (dynamic, not a fixed spacing token) — managed by `.aspectRatio(16/9, contentMode: .fit)` on the AVKit player container.
- Tab bar: height system-managed by SwiftUI `TabView`; do not override.

## Typography

All sizes in SwiftUI points. Font: SF Pro (system default via `.font()` modifier). Dynamic Type required on all text.

| Role | Size | Weight | Line Height | SwiftUI Token |
|------|------|--------|-------------|---------------|
| Body | 17pt | Regular (400) | 1.5 | `.body` |
| Label | 15pt | Regular (400) | 1.4 | `.subheadline` |
| Heading | 22pt | Semibold (600) | 1.2 | `.title2` |
| Display | 28pt | Semibold (600) | 1.1 | `.title` |

Phase 2 additions (same 2-weight constraint, same 4-size set):
- Exercise name in list row: `.subheadline` semibold (600) — pulls from Heading weight, Label size.
- Section header (muscle group name in sectioned list): `.subheadline` semibold (600), uppercased via `.textCase(.uppercase)`.
- Filter chip label: `.subheadline` regular (400).
- How-to bullet step body text: `.body` regular (400) — standard Body role.
- Form tips body text: `.subheadline` regular (400) with `.secondary` color — visually differentiated from how-to body text without introducing a new size.
- Primary muscle group label in exercise list row: `.subheadline` regular (400) with `.secondary` color — visually subordinate to the exercise name without introducing a new size.

**Constraints (inherited from Phase 1):**
- Maximum 4 sizes: 15pt, 17pt, 22pt, 28pt. No additional sizes.
- Maximum 2 weights: Regular (400) and Semibold (600). No medium, bold, or italic.
- All text must use SwiftUI semantic font tokens — never `.system(size: N)` — so iOS accessibility Dynamic Type scaling works automatically.

## Color

Phase 2 inherits Phase 1 dark-mode-first fitness aesthetic. No new semantic colors introduced.

| Role | Dark Mode | Light Mode | Usage |
|------|-----------|------------|-------|
| Dominant (60%) | `#0F0F0F` (near-black) | `#F5F5F5` (near-white) | App background, full-screen exercise detail surface |
| Secondary (30%) | `#1C1C1E` (system grouped bg) | `#FFFFFF` (white) | Exercise list rows, filter chip fill (unselected), video placeholder card |
| Accent (10%) | `#FF6B35` (energetic orange) | `#FF6B35` (same) | Selected filter chip fill + border, active muscle-group tag pill |
| Destructive | `#FF3B30` (iOS system red) | `#FF3B30` (same) | Not used in Phase 2 UI (no destructive actions) |

**SwiftUI semantic mappings (inherited):**
- Dominant: `.systemBackground` / `Color("AppBackground")`
- Secondary: `.secondarySystemBackground` / `Color("CardBackground")`
- Accent: `Color("AccentColor")` — app accent color in Assets.xcassets
- Destructive: `Color.red` — not triggered in Phase 2

Accent reserved for (Phase 2 additions):
1. Selected filter chip — fill `Color("AccentColor")` at 100% opacity; label text `.white`
2. Active muscle-group tag pill on exercise detail view — accent background, white label
3. Active tab bar item icon + label tint (inherited from Phase 1, Tab 2 active state)

Accent is NOT used for: unselected filter chips, exercise row backgrounds, video player controls (system default), section headers, body text, headings, how-to bullet markers, or placeholder thumbnails.

**Unselected filter chip:** Secondary background (`Color("CardBackground")`), Label-color text, 1pt border in `.tertiaryLabel` color.
**Placeholder thumbnail (unlicensed video):** Linear gradient from `#1C1C1E` to `#2C2C2E` (secondary-to-slightly-lighter). No accent. Static — no animation.

(Source: Accent `#FF6B35` from Phase 1 UI-SPEC. Chip selected/unselected states from CONTEXT.md `<specifics>`. Placeholder gradient from Claude's Discretion — CONTEXT.md delegated placeholder thumbnail design.)

## Interaction Contracts

### ExerciseLibraryView — Train Tab Root

**Layout (top to bottom):**
1. `.searchable(text:)` modifier on the NavigationStack — renders the system search bar in the navigation bar area. Placeholder text: "Search exercises".
2. Filter chip row: horizontal `ScrollView(.horizontal, showsIndicators: false)` containing an `HStack(spacing: 8)` of chip buttons. Padding: `md` (16pt) leading/trailing, `sm` (8pt) top/bottom.
3. Sectioned `List` of exercises, grouped by primary muscle group. Section headers use `.subheadline` semibold uppercased. List style: `.plain` (no inset grouped card appearance — cleaner for dense exercise lists).

**Filter chip behavior:**
- Chips are a two-row logical group: muscle-group chips first ("All", "Chest", "Back", "Shoulders", "Arms", "Core", "Legs", "Glutes", "Full Body"), equipment chips second ("Bodyweight", "Dumbbells", "Barbell", "Machine") — all rendered in a single horizontal scroll row in order, separated by a 1pt vertical divider between the two groups.
- "All" chip: always first; selecting it clears all other active filters.
- Muscle group and equipment filters are independent (AND logic): selecting "Chest" + "Dumbbells" shows dumbbell chest exercises only.
- Tapping a selected chip deselects it (toggles off). Deselecting both filters defaults to "All".
- Chip tap: no animation delay — immediate state update via `@Observable` ViewModel.

**Exercise list row:**
- Height: minimum 60pt (content-driven, not fixed).
- Layout: leading thumbnail (52pt × 52pt, `.cornerRadius(8)`), trailing VStack with exercise name (`.subheadline` semibold) + primary muscle group label (`.subheadline` regular, `.secondary` color).
- Thumbnail: Mux-served poster frame (async image load). Placeholder while loading: secondary color rounded rect with `dumbbell` SF Symbol centered (`.body` size, `.tertiaryLabel` color).
- Chevron: system `.chevronRight` trailing disclosure indicator (SwiftUI `List` default).
- Tap: NavigationStack push to ExerciseDetailView — standard slide-right transition (no custom animation; Claude's Discretion — use SwiftUI default per CONTEXT.md).

**Search behavior:**
- Search is live-filtered (reactive to `searchText` change) — no "Search" button tap required.
- Fuzzy match covers exercise name and muscle group tags.
- While search field is active: filter chip row collapses (hidden) to give vertical space.
- Empty search result state: see Copywriting Contract below.

### ExerciseDetailView — Exercise Detail

**Layout (top to bottom, within NavigationStack):**
1. Video player: `AVPlayerViewController` wrapped in `UIViewControllerRepresentable`, full width, `.aspectRatio(16/9, contentMode: .fit)`. Auto-loop enabled. Auto-plays on view appear. Standard AVKit transport controls visible (system default).
2. Below video (scrollable): exercise name (`.title2` semibold), primary muscle group tag pills (`HStack`, accent fill), `Divider`, 3–5 how-to steps as a numbered `VStack` (`.body` regular, 1.5 line height), `Divider`, form tips section heading ("Form Tips", `.subheadline` semibold), form tips body (`.subheadline` regular, `.secondary` color — visually subordinate to how-to body text without adding a new font size).
3. All scrollable content: horizontal padding `xl` (32pt), matching the established Phase 1 full-screen content padding pattern.

**Video states:**
- Loaded + playing: standard AVKit player, auto-loop via `AVPlayerLooper`.
- Paused (user tapped pause): AVKit shows play button overlay (system default — no custom overlay needed per CONTEXT.md decision: "custom play/pause button overlay when paused" — implement as a tappable overlay `Image(systemName: "play.circle.fill")` at 60pt, `.white` at 0.9 opacity, centered on player, shown only when player `.timeControlStatus == .paused`).
- Buffering: `ProgressView()` centered on player area, `.white` tint.
- Tap-to-fullscreen: system AVKit fullscreen button (bottom-right of transport bar) — no custom implementation required.
- Placeholder (unlicensed video): replace player with gradient card (`LinearGradient` from `#1C1C1E` to `#2C2C2E`), centered `VStack` with `video.slash` SF Symbol (40pt, `.secondary`) + "Video coming soon" label (`.subheadline`, `.secondary`). Same 16/9 aspect ratio frame.

**Navigation:**
- Back button: system SwiftUI "Back" label, standard navigation bar leading button.
- Navigation bar title: exercise name, `.inline` display mode.

### Offline / Cache State

Not a separate screen — cache is transparent to the user during playback. If a cached video fails to play (corrupted cache), treat as a network error (see Error states in Copywriting Contract). Cache size display on ProfileView: a single `.subheadline` label line "Exercise video cache: [X] MB" under a "Storage" section — no new UI pattern needed beyond a standard `List` row.

## Accessibility Contract

- All interactive elements have `.accessibilityLabel` set.
- Filter chips: `.accessibilityLabel("[Muscle Group] filter")` + `.accessibilityAddTraits(.isButton)` + `.accessibilityValue(isSelected ? "selected" : "not selected")`.
- Exercise list row: `.accessibilityLabel("[Exercise Name], [Primary Muscle Group]")`.
- Video player: AVKit's `AVPlayerViewController` is inherently accessible (VoiceOver announces playback state).
- Play/pause overlay button: `.accessibilityLabel("Play video")` / `.accessibilityLabel("Pause video")`.
- Placeholder thumbnail: `.accessibilityLabel("[Exercise Name] — video coming soon")`.
- Minimum touch target: 44pt × 44pt on all tappable elements. Filter chips use `.contentShape(Rectangle())` to extend hit area beyond visual bounds.
- Dynamic Type: all text uses semantic SwiftUI font tokens — never `.system(size: N)`.
- Color contrast: accent `#FF6B35` on `#0F0F0F` = 4.6:1 (meets WCAG AA for UI components). White text on accent chip fill: `#FFFFFF` on `#FF6B35` = 3.0:1 (meets WCAG AA for large text / UI components per WCAG 2.1 §1.4.11).
- Pull to refresh: `.refreshable` modifier on the exercise list — announces to VoiceOver as "Refresh" action.
