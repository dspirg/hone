## Critical Gaps (Functional Breaks)

### 1. ADPT-03: Missed session data format mismatch
**Severity:** HIGH — feature is non-functional
`MissedSessionDetector` returns day-label strings (`"Monday"`, `"Wednesday"`). The `adapt-plan` Edge Function validates `missed_sessions` with `ISO_DATE_RE = /^\d{4}-\d{2}-\d{2}$/`. Day labels fail the regex and are silently dropped. The AI never receives missed session data.

**Fix:** Convert day labels to actual ISO dates before sending, or change Edge Function to accept day labels.

### 2. ADPT-01/02: Adapted plan not written to CoreData
**Severity:** HIGH — adaptation visible only after app relaunch
`AdaptationService` decodes `AdaptedPlanResponse.weeklyDays` but only sets `lastAdjustmentSummary`. The adapted plan is never persisted to CoreData. `TrainView` still shows the old plan. The pattern exists in `CoachViewModel.applyPlanUpdate()`.

**Fix:** Add `WorkoutPlanRepository.save()` call in AdaptationService after receiving adapted plan.

### 3. PROG-03: Workout reminders never scheduled
**Severity:** MEDIUM — feature implemented but not wired
`NotificationScheduler.scheduleWorkoutReminders(planDays:currentStreak:)` is fully implemented but has zero call sites. Permission is requested correctly, but no recurring reminders are ever scheduled.

**Fix:** Call `scheduleWorkoutReminders` after plan generation and after plan adaptation.

### 4. PROG-02: Weekly ring hardcoded to 4 days
**Severity:** LOW — visual inaccuracy
`ProgressViewModel.computeWeeklyRing()` always uses `weeklyPlanned = 4`. Users on 3-day or 5-day plans see an incorrect weekly completion ring.

**Fix:** Fetch `daysPerWeek` from active `CDWorkoutPlan`.
